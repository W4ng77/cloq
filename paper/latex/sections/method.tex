\section{Measuring the Task Value of an Upgrade}
\label{sec:method}

\subsection{Setting}
\label{sec:setting}

\paragraph{Tasks and agents.} We use \tautwo{} in text mode: a development panel of 58 retail and 27 airline tasks plus 80 telecom development tasks, and a holdout of 34 telecom tasks that no agent ran before its protocol was frozen. % src: manifests/fork/splits_v1.json
The agents are Qwen3-4B-Instruct (q4) and Qwen3-8B with thinking disabled (q8); a second family, Mistral-Small-3.2-24B, is a scope check (Table~\ref{tab:scope}). % nocheck: model name
One greedy Qwen3-30B-A3B-Instruct user simulator serves all agents. % src: ../cloq_work/sims/*.json (hf_id); docs/FINAL_EXPERIMENTS.md
Retail and airline success is the final-database match with normal termination, without all of \tautwo{}'s official communication checks; telecom uses the official task-basis success. BFCL multi-turn and ALFWorld have no user simulator and run once per item (Appendix~\ref{app:setup}).

\paragraph{Quantization and serving.} Q is a simulated (fake-quantized) checkpoint served with BF16 compute on the same path as B. A \emph{configuration} is one model under one quantization setting. The main configurations use GPTQ \citep{frantar2023gptq} and AWQ-style scaling \citep{lin2024awq} at W4 (group size 128), calibrated on BF16 agent trajectories of 57 retail and airline tasks disjoint from the development tasks, and an INT8 KV cache (KV8). Stress configurations (GPTQ-W3, RTN-W3, rotated KV4) and QuaRot, SpinQuant and KIVI \citep{ashkboos2024quarot,liu2025spinquant,liu2024kivi} are scope checks (Table~\ref{tab:scope}; Appendix Table~\ref{tab:qconfig}). % src: runs/a6k2_q4_gptq_w4_d1_f01/quantization.json; runs/a6k2_q8_awq_w4_f01/quantization.json; runs/a6k2_q8_kvq_int8_f01/quantization.json; manifests/a6k2/q4/calib_fp_traj_c1.json
B and Q run on vLLM \citep{kwon2023vllm} with batch-invariant kernels \citep{he2025defeating} and deterministic compilation in separate server processes, so no prefix cache is shared. A \emph{block} is one closed-loop run of Q over the task pool under one prompt nonce (a random session-identifier line in the system prompt); blocks are the replicates, and a \emph{unit} is one task in one block.

\subsection{Four branches on one state}
\label{sec:estimands}

\paragraph{Frozen state.} Before Q's decision $t$ we restore the state $s_t$: the full message history; the environment and user-device databases, rebuilt by strict replay of every recorded tool call; the user simulator's visible conversation; and the used step and error budget. B and Q generate their actions from identical prompt token ids, and the state is written to disk before any branch runs.

\paragraph{Four branches.} $\YY{XY}\in\{0,1\}$ is task success when the action at $s_t$ comes from X and model Y executes the rest of the episode, X, Y $\in\{\mathrm{B},\mathrm{Q}\}$ (Figure~\ref{fig:case}). The action is executed by the real environment or answered by the real simulator; all four branches share the remaining budget. Each upgrade option is a paired contrast with QQ: % nocheck: notation {0,1}
\begin{align*}
G &= \YY{BQ}-\YY{QQ} && \text{(this step only)},\\
H &= \YY{QB}-\YY{QQ} && \text{(from the next step)},\\
F &= \YY{BB}-\YY{QQ} && \text{(both)}.
\end{align*}
For a replacement, a \emph{rescue} is a unit where the upgraded branch succeeds and QQ fails, and a \emph{damage} is the reverse. \emph{Turnover} is rescues plus damages; \emph{net} is rescues minus damages. When the effect of the action swap differs between Q's and B's continuation, we call the outcome \emph{continuation dependent}. All contrasts measure effects on task success, not which action is correct. Appendix~\ref{app:names} defines the symbols used in the appendix.

\paragraph{Reference interventions.} A large turnover could mean that a decision needs higher precision, or only that it is sensitive to a change of model. We therefore rerun the design with Q$'$ in place of B: a second GPTQ-W4 checkpoint of the same model, calibrated on a re-drawn state and row sample from the same calibration trajectories, with the same Q episodes, tasks and nonce blocks and a protocol frozen before any outcome (q4 and q8 GPTQ-W4; GPTQ-W3 as a stress check). \S\ref{sec:sameprec} adds a comparison at common states and a key-order change of Q's own action.

\subsection{Making the counterfactuals auditable}
\label{sec:replay}

\paragraph{Replay acceptance.} Before any development outcome was analysed, an engineering gate on real divergence states passed every check: Q$\rightarrow$Q no-ops matched in 20/20 states and B$\rightarrow$B no-ops in 10/10, in every prompt-token hash, message, database hash, termination, reward and budget counter. % src: docs/insights/FORK_PROTOCOL.md §8 (analysis/fork/gate/)
In production, every fork task re-ran the QQ no-op on an outcome-independent 10\% hash sample of its states, and one mismatch would have quarantined the task's whole output; all 924 sampled development states passed, as did all sampled states of the other state sources and of the same-precision run (Appendix~\ref{app:setup}). % src: docs/insights/FORK_PROTOCOL.md §9 (QQ no-op on a 10% hash sample; stop rule); analysis/fork/out/dev_all_20261001T070326Z.md
Exact replay is a tested property of this stack (greedy decoding, vLLM 0.29.0, batch-invariant kernels, deterministic compilation, dense BF16 kernels), not a general one \citep{yuan2025nondeterminism}; determinism tests and untested conditions are in Appendix~\ref{app:setup}. % src: analysis/status/gpu_fill_20261003/rerun_premise_det.json; docs/RESEARCH_LOG.md (W100w determinism-premise table); analysis/fork/commonstate_replay_check/REPLAY_8of9.md (TL;DR; serving context)

\subsection{Which states}
\label{sec:states}

\paragraph{State sources.} A \emph{first divergent state} is, for each task, block and configuration, the first decision at which B's and Q's actions differ in kind (tool call, text or stop), tool name, call count or order, or normalised arguments; two text replies that differ only in wording do not count. An \emph{ordinary sampled state} is one decision per task and block, drawn by a hash fixed before generation, from Q's own trajectories or from BF16 trajectories shared by all configurations of a model. A \emph{common state} is an ordinary sampled state at which several action sources are compared. % src: docs/insights/FORK_PROTOCOL.md §15 amendment 1

\paragraph{Denominators and inference.} Rescues, damages, turnover and net use the \emph{full pool} of task$\times$block units; units without a first divergent state count as zero. $G$, $H$, $F$ and continuation dependence use the \emph{divergent states} of a configuration; ordinary sampled states have one state per task and block. Within a configuration all branches share each state and all tasks of a block share its nonce, so contrasts are paired and identified; across configurations, which select their own divergences, comparisons are descriptive. Only complete blocks enter. The primary \emph{fixed-pool} interval treats the task pool as fixed (block bootstrap with at least 10 blocks, else $t$ over block means); the \emph{new-task} interval is a crossed task$\times$block bootstrap (``crossed''). \emph{Resolved} means that the named interval excludes zero; ``not resolved'' means that the reported interval or intervals include zero. Where a frozen protocol sets its own reading rule, we state it with the result. % nocheck: interval rule as in archived method L39
