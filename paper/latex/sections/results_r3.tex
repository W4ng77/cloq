\section{Sensitivity Enrichment Does Not Establish Net Gain} % nocheck: section number
\label{sec:r4}
\label{sec:trigger}



The frozen uncertainty rule finds decisions whose outcomes change, but it does not reliably select a net benefit. Figure~\ref{fig:trigger} tests these two objectives separately.

\paragraph{Selecting outcome-changing decisions.} $G$, $H$ and $F$ require running B. We test selection under a Q-only constraint: the rule uses no BF16 computation before choosing an upgrade. We choose and freeze the rule on development data, then evaluate it on later prompt blocks. % src: analysis/fork/out/token_mech_20261001T185031Z.md (§1a; §1b differing vs exact)
On one development block, we choose among entropy, margin and mean log-probability by net gain over random selection. We freeze the winning margin rule before validation: at low minimum token margin, B supplies the action and Q continues. This implements $G$; margins are known to predict cross-precision divergence \citep{du2026greedy}. Per-configuration thresholds target 5, 10 and 20\% of development states. Validation can select a different fraction, so random and oracle baselines match the actual counts (Figure~\ref{fig:trigger}). % src: analysis/fork/out/token_mech_20261002T003130Z.md; manifests/fork/token_trigger_rule_v1.json

We test on two later blocks of the same development tasks, separate from telecom holdout. The states come from Q's own histories. Six configurations (four W4 and two KV8) yield 1020 states, including 69 outcome changes. At the 20\% nominal rate, the rule captures 27 changed outcomes against 14.30 expected from matched random selection ($p=.0002$). The other rates and a secondary test on BF16 histories appear in Appendix~\ref{app:token}. % src: analysis/fork/out/token_mech_20261002T003130Z.md (§3 Validation, U1 S_mm PRIMARY; U2B S_mm secondary); manifests/fork/token_trigger_rule_v1.json (population; candidates; selection_criterion)

\paragraph{Testing benefit against random selection.} The captured states were rescues and damages alike (Figure~\ref{fig:trigger}a). None of the three rates shows a reliable net benefit over matched random selection after Holm correction (Figure~\ref{fig:trigger}b). No rate was designated primary; exact tests and the nominal 5\% result appear in Appendix~\ref{app:oracle}. A hindsight oracle with the same per-configuration counts nets far more (Figure~\ref{fig:trigger}b), positive by construction because it picks only rescues. % src: analysis/fork/out/token_mech_20261002T003130Z.md (§3 Validation, U1 S_mm PRIMARY); analysis/fork/out/oracle_trigger_20261002T024423Z.md (§1a, §2)

\paragraph{What this test establishes.} Enriching outcome-changing decisions is not enough for reliable net gain \citep[cf.][]{zhang2026credit}. The later blocks reuse the development tasks, and only this simple frozen rule is tested. Learned and other uncertainty-based escalation rules require their own net-benefit tests \citep{li2026dynamicmp,piatrashyn2026redact,lei2026tacit}.
