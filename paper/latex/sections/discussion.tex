\paragraph{What the references establish.} Outcome changes alone do not identify a need for more bits. Q$'$ changes outcomes without increasing precision. Key-order reversal changes some outcomes without changing the tool operation. These are interpretation checks, not a noise floor to subtract. BF16's additional benefit requires a direct comparison on shared states; our intervals still allow useful gains.

\paragraph{What a deployment should measure.} Evaluate the upgrade that will actually run: replace an action, take over the continuation, or both. Report rescues, damages and their net gain on paired states. A selector should predict that signed benefit, rather than disagreement or turnover. The frozen margin rule illustrates the gap: it finds outcome changes without reliable net benefit on later blocks of the same tasks. Learned routing and comparisons at a shared BF16 compute budget remain open questions.

\paragraph{From a realised consequence to expected value.} Exact replay audits a consequence under fixed execution conditions. Deployment value requires averaging paired success differences over specified prompt and user conditions. Average benefit and individual label stability are separate questions. Table~\ref{tab:scope} summarises coverage; detailed results and inference rules appear in the appendix.

\section{Conclusion}
\label{sec:conclusion}

Our audited forks separate three precision upgrades. On the main W4 panel, rescues and damages largely cancel. Reference substitutions show why turnover alone cannot establish a need for more bits. A frozen uncertainty rule finds changes without reliable net benefit. Fallback evaluation should measure paired task consequences and validate the net benefit of the upgrade actually executed.
