\section{Discussion}
\label{sec:discussion}

\paragraph{Sensitivity and value answer different questions.} The two reference interventions are central to interpreting an upgrade. Q$'$ shows that higher precision is not necessary for two-sided outcome changes. Key-order reversal shows that some changes arise even when the executed tool operation stays identical. Neither reference establishes that precision is irrelevant, and neither is a noise floor to subtract from BF16's turnover. The common-state experiment asks the direct value question, but its intervals still permit a useful BF16 advantage. An unresolved comparison therefore warrants neither automatic escalation nor a claim that escalation cannot help.

\paragraph{What a selector needs to predict.} A sensitivity score can find disagreements or outcome changes while selecting rescues and damages together. Our frozen margin rule demonstrates this distinction on later nonce blocks of the same tasks. Selection labels should match the intervention a deployment will execute. An action-only rule and a continuation router therefore need different outcome targets. Learned selection and cost-aware routing are natural extensions: evaluation would compare signed task benefit at a shared BF16 compute budget, adding deployment costs to the task-value measurements made here.

\paragraph{Task value across execution conditions.} Each rescue or damage is a paired, realised consequence under the specified greedy stack. Exact replay establishes the consistency of that comparison. Key-order reversal demonstrates that a label can change with the representation the agent reads, even when the tool operation is identical. For an expected value over a deployment distribution, specify the prompt and user conditions, repeat paired branches across them, and average the success differences. A selector's target is this signed average benefit; the stability of individual rescue and damage labels is a separate property. Our experiments measure conditional task consequences and provide a protocol for making those deployment-distribution comparisons.

\paragraph{Recommendations for evaluation.} Report the rescues, damages and net gain of the actual upgrade mode on paired states. Include reference substitutions to test whether sensitivity alone supports the intended precision claim. Distinguish the fixed task pool from a new-task target, and evaluate a selection rule by net benefit at matched counts. \section{Conclusion}
\label{sec:conclusion}

Precision upgrades have an intervention-specific task value. Our audited forks separate replacing an action from taking over the continuation, while reference substitutions show why outcome changes alone cannot establish a need for more bits. On the main W4 panel, rescues and damages largely cancel; the common-state comparison leaves BF16's additional value unresolved. One frozen uncertainty rule enriches outcome changes without reliable net benefit. Together, these results motivate evaluating fallback decisions through paired task consequences, reference interventions and the net gain of the policy actually executed.
