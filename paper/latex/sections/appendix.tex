\section{P0 Audit: Statistics and Measurement Fixes}
\label{app:audit}

An external review of an earlier version of this project identified statistics and measurement problems; all were confirmed in the code and fixed before the fork study. Everything below that touches the 28 pre-registered confirmatory runs (Appendix~\ref{app:prereg}) is a \emph{corrected, post-hoc} re-analysis; the pre-registered outputs are kept unchanged as history. The re-analysis reproduces the pre-registered numbers exactly before applying fixes (H3 $F=0.2602$, $p=0.0008$; H1 $p=0.74385$).

\paragraph{H3 correction (split-task fingerprint).} The pre-registered test scaled each behaviour feature by the differences of the \emph{true} checkpoint pairs and then permuted checkpoint labels of a cosine matrix computed with that scale held fixed. The scale depends on the observed pairing, so permuted statistics are not exchangeable with the observed one. The corrected (main) test uses a pairing-invariant, unpaired pooled scale per split and feature, which makes the column permutation a valid permutation test; a sensitivity test recomputes the original preprocessing inside every permutation. Features, the 100 split halves and relabelling streams are fixed across variants.

\paragraph{Calibration by simulation.} Synthetic datasets resample the real per-task shift rows within block, so draws are exchangeable. At $\alpha=0.05$ the original test rejects 0.364 $\pm$ 0.011 (20 splits, $B=199$, 2000 datasets), 0.331 $\pm$ 0.006 (independent seeds, $B=99$, 6000 datasets) and 0.417 $\pm$ 0.011 (100 splits, $B=499$) of null datasets; the corrected test rejects 0.053 $\pm$ 0.005, 0.044 $\pm$ 0.003 and 0.061 $\pm$ 0.005 against nominal levels of at most 0.045, 0.040 and 0.048. The 100-split rows share datasets and sit 1.9--2.4 SE above nominal; we read them as a possible excess of at most 0.01. On i.i.d.\ synthetic shifts, the corrected test rejects 0.0405 $\pm$ 0.0025 (nominal $\le$ 0.040), the original 0.81. Power of the corrected test at planted signals $\delta=0.01/0.02/0.03/0.05$: 0.07/0.12/0.24/0.75. The pre-registered ``H3 supported'' label is removed; the corrected pooled result is post-hoc and is carried by the random checkpoints (Appendix~\ref{app:fingerprint}).

\paragraph{Crossed variance components.} The pre-registered overdispersion estimator subtracted a nonce term that included the shared nonce main effect, biasing $\phi$ low. Replacing it by a crossed model $m_{jn}=\mu+a_j+b_n+e_{jn}$ leaves the H1 permutation $p$ unchanged (the removed term is invariant under checkpoint relabelling): pooled RECAL $\phi$ is 0.396 (pre-registered), 0.469 (main effect removed; $p=0.744$, identical) and 0.327 (fully crossed; $p=0.721$). The H1 verdict is unchanged. Crossed components over GPTQ/AWQ-W4 d1--d4 (Henderson method III; signed SD in pp, $\mathrm{sign}(v)\sqrt{|v|}$):

\paragraph{Measurement fixes.}
\begin{itemize}[leftmargin=*,itemsep=1pt,topsep=2pt]
\item \emph{Open-loop act probability.} A tool-start token outside the stored top-20 was counted as probability 0. Now reported with lower/upper bounds and a missing flag; means move by less than 0.001, although the flag is frequent (17--34\% of q4 positions for W4 and Gaussian cells).
\item \emph{Top-$k$ KL.} Renamed to an approximation; an exact coarse-grained KL over tokens known on both sides plus one residual category (a lower bound) is added. Rankings are unchanged.
\item \emph{Tool-name mass.} The prefix-tree estimate is demoted to a proxy with measured error terms; the main tool metric is the fully generated and parsed name and arguments, as in the forks.
\item \emph{Confirmation feature.} A regex on the agent's own text was named as if it measured authorisation; it is renamed a confirmation-request proxy. Real authorisation needs user replies, tool rules and state, as in \S\ref{sec:annotation}.
\item \emph{Write classification.} Replaced by the verified tool-type table (Table~\ref{tab:tooltypes}); 1.6\% of q4/q8 episodes contain an invalid tool call.
\item \emph{Divergence analysis.} The earlier first-divergence analysis compared two independent trajectories, which stop sharing a history after the first difference; it cannot serve as a same-state fork. The fork design replaces it.
\item \emph{Success naming.} ``Success'' for retail/airline was the DB end-state match; it is now named DB success, with official rewards reported separately (\S\ref{sec:conditions}).
\end{itemize}

\paragraph{Act/talk selection effect.} Conditioning the quantized model's act probability on the reference's own choice selects positions where the reference's probability is near 0 or 1, so any perturbation, even a sign-symmetric one, pulls both conditional means toward the middle. For q4 RTN-W4, $P(\text{act}\mid\text{BF16 talked})$ rises from 0.014 to 0.088, while a sign-symmetric perturbation of the cell's own logit shifts predicts 0.080. The remaining directional part is a small net shift toward talking (unconditional $\Delta P(\text{act})$ between $-0.10$ and $+0.005$ on q4/q8 W4 cells), and size-matched random perturbations move it as much or more. Source: \nolinkurl{analysis/insights/iter_4/out/act_talk_selection_20260930T0044Z.json}.

\section{Random-Perturbation Fingerprint (Exploratory, Post-Hoc)}
\label{app:fingerprint}

The corrected exploratory analysis detected cross-run behavioural consistency in random-perturbation checkpoints ($F=0.283$, $p=0.028$ for RAND only); no corresponding evidence was detected for W4 quantized checkpoints (RECAL only $F=0.025$, $p=0.30$; sensitivity $p=0.13$; within-method $p=0.19$). The RAND $p$ is post-hoc, is the minimum attainable with 36 relabellings, and must be read with multiplicity. The pooled corrected result ($p=0.013$) is 90\% carried by RAND and supports no claim about quantization. With two recalibrations per method and model, a within-method test cannot reach $p<0.5$.

\section{Determinism and Serving Details}
\label{app:serving}

\paragraph{The incident.} In an earlier pass, a BF16 q4 determinism pair served on two nodes disagreed on 20/20 tasks and 113/113 identical-prompt decisions. The kernels were identical across nodes; torch Inductor chose the reduction configuration of the fused residual+RMSNorm kernel by timing it at compile time (a block size of 2048 on one node versus 4096 elsewhere), which changed the summation order and shifted every token. vLLM's batch invariance does not cover this. Setting \texttt{TORCHINDUCTOR\_DETERMINISTIC=1} and checking a numerics canary (outputs compared by hash with a stored reference) for agent and simulator at every server start removed it: the re-run pairs were byte-identical in prompts and completions (257/257 decisions for q4, 303/303 for Qwen3-30B-A3B as agent). The whole matrix was re-run under the fix.

\paragraph{Configuration.} vLLM 0.29 with \texttt{VLLM\_BATCH\_INVARIANT=1} and pinned compile flags; greedy decoding for agent and simulator; 32k-token prompt budget; two-GPU tensor parallelism only on NVLink-connected pairs. In the fork study, B and Q are served by separate server processes, so no KV or prefix cache is shared across weights. \pending{fork serving record: checkpoint hashes, canaries and prefix-cache counters per server --- \nolinkurl{logs/tasks/<fork task>.servers.json}}
