\section{Telecom Holdout: Protocol, Readings and Replay Audit (supports \texorpdfstring{\S\ref{sec:value}}{the consequences result})}
\label{app:prereg}

This appendix supports the holdout statement of \S\ref{sec:value}: the net estimate is negative, the frozen readings classify it as inconclusive because they had no negative category, and both pre-registered secondary checks passed.

The protocol was frozen before any holdout unit was run, and its hash was recorded in the split manifest. % src: manifests/fork/splits_v1.json; docs/RESEARCH_LOG.md W87
It fixes the following design:
\begin{itemize}[leftmargin=*,itemsep=1pt,topsep=2pt]
\item tasks, cells, weights and nonce blocks;
\item two fixed halves of six blocks each;
\item an outcome-blind repair rule, with reserve blocks used only for infrastructure repair;
\item the decisional crossed interval (two-way ANOVA moments, normal 90\%);
\item the readings: positive if $L>0$, above 3\pp{} if $L>3$, small if the interval lies inside $\pm$3\pp{}, otherwise inconclusive;
\item the secondary families S1 (both $r>0$ and $d>0$) and S2 (persona-stratified permutation, 10{,}000 draws, no outcome screen);
\item six stratum families, with Holm correction within each.
\end{itemize}
% src: docs/insights/PREREG_FORK_CONFIRM.md §0, §3, §6-§9
The analysis script refuses holdout data unless the hash matches. Two task-cell pairs were excluded as structural, and the complete-case analysis is identical. % src: analysis/fork/out/holdout_confirm_cc_20261002T012358Z.md

\paragraph{Replay acceptance on the holdout (post hoc audit).} $\YY{QQ}$ is the one arm taken from the original episode rather than re-executed, and an exploratory count showed only-QQ successes more often than random labelling would give in two q8 holdout cells. We therefore audited the holdout's acceptance records after the analysis, with a script that outputs only consistency checks and counts. The fixed hash rule selected 135 of the 1202 divergent states for the QQ no-op; all 135 were run and passed, none was missing, failed or non-computable, and no other state was re-run. Beyond the frozen checks (suffix, prompts, termination, outcome, budget counters), the 135 also match on reward, database state, the official reward, the final environment hash against a strict replay of the original episode, and the history prefix. The original QQ and the re-run arms are scored by the same official reward rule: recomputing it from the stored reward information reproduces the stored value for every arm. The audit read the same input files as the frozen analysis, so no repair under the protocol's missing-data rules was needed, and the pre-registered result stands as reported. A later full replay, under a protocol frozen before any task ran, re-ran QQ on all 1202 divergent states, with each task's Q checkpoint hash, serving-configuration hash and numerics canary checked equal to the original fork's at server start: all 1202 matched on every check above, none was missing or failed, and the original 135 matched again. The replays therefore rule out a replay artifact in the shared QQ baseline; they do not explain the only-QQ pattern, which a real upgrade that damages the original policy would also produce. Re-including the two structurally excluded task--cell pairs in all twelve blocks (post hoc sensitivity, frozen estimator) with every unit set to $-1$ or $+1$ gives point estimates of $\Gall$ from $-6.68$ [$-10.35$, $-3.01$] to $-2.27$ [$-5.96$, $+1.43$]\pp{} (crossed 90\%). This is a range of point estimates: the interval of the most optimistic scenario includes zero. With their observed units kept in the eleven blocks where they exist and only the two missing units set to $-1$ or $+1$, the estimates are $-4.72$ to $-4.35$\pp{}, each with a crossed 90\% interval below zero. The frozen reading is inconclusive in all 36 combinations. % src: analysis/fork/out/holdout_structural_worstcase_20261005T031411Z.md % src: analysis/fork/out/holdout_noop_audit_20261004T152207Z.md; analysis/fork/out/holdout_qqfull_audit_20261006T061033Z.md (TL;DR); docs/insights/HOLDOUT_QQFULL_PROTOCOL.md (§1-§5, Amendment 1)
