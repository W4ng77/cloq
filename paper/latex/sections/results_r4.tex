\label{sec:scope}
\label{sec:duration}

\paragraph{Takeover duration.} On 255 q8 U2B states of the \S\ref{sec:r4} KL panel (3 blocks; exploratory), Q's action is followed by $L$ BF16 decisions and then by Q again. SpinQuant-W4A4 was chosen \emph{after} its sustained-takeover value on this panel ($H=+11.8$\pp{}) was seen, and the sustained arm reuses that endpoint, so its results are conditional on that selection. Against Q's own continuation, a one-decision takeover there shows no detectable net gain ($0.0$ [$-3.5$, $+3.5$]), four decisions gain $+6.3$ [0.0, 12.2], not yet resolved, and fall $5.5$\pp{} short of sustained takeover ($+11.8$ [5.1, 18.4]; paired difference crossed 95\% [0.8, 10.6]). % src: analysis/fork/out/takeover_20261005T1604Z.md (Reading); analysis/fork/out/takeover_20261005T1604Z.json (cells.spinquant_w4a4.primary.all_states_pp, crossed_ci95)
Four-decision windows handed control back at 66\% of states; the rest ended inside the window, so they cannot show that four steps suffice. Under GPTQ-W4 the continuation value itself is small ($+0.8$ [$-5.9$, $+7.5$]) and no window effect is resolved (Appendix~\ref{app:takeover}). Handoff is known to cost quality \citep{ganz2026handoff}. In the selected cell, takeover value also depends on its length; GPTQ-W4 does not resolve whether this generalises. % src: analysis/fork/out/takeover_20261005T1604Z.md (Handback per window: spinquant_w4a4 Q4 buckets 169/255); analysis/fork/out/takeover_20261005T1604Z.json (cells.gptq_w4_d1.primary.all_states_pp.V_Qinf); derived: 66=100*169/255

\paragraph{Representation change.} On 300 verified tool-call states of q8 GPTQ-W4 (41 tasks; airline 187, retail 113), we reverse the order of the top-level argument keys in Q's action. The parsed call and its effects are identical; only the next tokens the agent reads change (exploratory; analysis frozen in advance). This changes the outcome in 6.7\% of these states ([0.8, 14.4]), against 9.0\% [2.9, 18.2] for B's action on the same states; the difference, $-2.3$\pp{} [$-8.4$, $+2.9$], is not resolved, and we claim no equivalence. Some outcome changes therefore arise without any change to the tool operation. The result covers only these states and this one change, not free-text or other representation changes (Appendix~\ref{app:keyorder}). % src: analysis/fork/out/keyorder_20261005T204349Z.md; analysis/fork/keyorder/eligibility_v1.md; docs/insights/KEYORDER_PERTURB_PROTOCOL.md (intervals: widest of block and crossed bootstrap on the pooled ratio)
