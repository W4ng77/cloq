Use this directory with [W4ng77/cloq](https://github.com/W4ng77/cloq). The code was checked against default-branch files from the paper repository. The upstream paper commit inspected in this session is `3059b97c792d165a322314cd5eb4b1a7e1de7b7b`. Verify that the analysis inputs reproduce the submitted numbers before comparing results.

## 1. Official reward sensitivity

Copy or mount the authorized original data with the original directory structure. The CPU launcher takes a CLOQ checkout, a data root containing `runs/` and `analysis/fork/dev/` (plus `analysis/fork/repair/` if present), and the corresponding frozen snapshot containing original trajectory hashes. The compact published tables alone cannot reproduce the communication-sensitive score. Use an interpreter with NumPy and SciPy.

```bash
export CLOQ_PYTHON=/absolute/path/to/venv/bin/python
export SLURM_ACCOUNT=YOUR_NARVAL_ALLOCATION
bash scripts/narval_precision/submit_official_reward.sh CLOQ_CHECKOUT RAW_DATA_ROOT FROZEN_SNAPSHOT OUTPUT_DIR
```

The script uses the upstream analysis admission and no-op checks, limits scope to the four paper W4 configurations on the 58 retail and 27 airline development tasks, and requires complete task-by-block panels. For each configuration and domain it reports rescue, damage, net success, and the paired change between the two definitions for BQ, QB, and BB, with complete-block and crossed task-by-block intervals. The full-pool switch policies do nothing at units without a first divergence. The conditional estimates use observed divergences. Missing official scores exclude a pairing and can render an entire block incomplete. Compare inclusion to the original 20 blocks per configuration and reproduce DB estimates on the original cohort or explain the coverage difference. Use the pinned τ²-bench evaluator to spot-check saved `official_reward` against task-specific reward basis. Use failing communication checks from `reward_info` to characterize endpoint disagreements, and report overlaps with other failing criteria.

## 2. RTN-W3 expansion

The included `stress_panel.json` is generated by `freeze_stress_panel.py` from the repository split. It freezes 1 six-task smoke block, 3 complete qualification blocks and 20 fresh complete expansion blocks. Only the 20 new blocks enter the primary extension estimates. The submitted 3 stress blocks and new qualification blocks are reported separately. On this same development task panel, the expansion measures replication over prompt blocks. Evidence for generalization to an independently held-out task set requires additional tasks.

1. **Smoke.** Use pinned Qwen3-8B BF16 weights, the original RTN-W3 quantization recipe (asymmetric group 128, dequantized BF16 checkpoint, same dense inference path), the original Qwen3-30B-A3B-Instruct BF16 simulator revision and the pinned τ²-bench environment. Run both end-to-end arms and all four branches on the smoke tasks where there is a divergence. Check replay of all available QQ smoke forks, matching prompt IDs, action, termination, budget and reward. Confirm that there are actual divergent states and check that deterministic reruns produce the same decisions. Save serving and checkpoint fingerprints. Historical A6000 canaries may differ numerically from Narval hardware. Verify repeatability on Narval and keep original and new runs separately identified.
2. **Qualification.** Run paired BF16 and RTN-W3 end-to-end from the start on all 85 tasks in the three qualification blocks. Measure BF16 minus RTN-W3 with paired new-task and fixed-pool intervals under both endpoints. Use the predeclared DB point estimate of at least 5 pp as an operational launch gate. Show the interval and distinguish a pilot gate from an established deficit. If it fails, report the result and pause before changing the setting.
3. **Expansion.** Run the same paired baselines and the first-divergence fork on all 20 expansion blocks. The primary contrast is `(BB − QQ) − (BQ − QQ) = BB − BQ`, conditional on first divergence. Report it with a paired crossed interval. Also report each mode's rescue/damage/net rates, the DB-to-official sensitivity and coverage, the action-only full-pool effect, and the paired from-start BF16–W3 deficit over the new blocks. The no-op replay audit uses the existing hash sampling at 10%. Capture BF16 generated decision count and tokens separately by mode. Count the forced BF16 action from its generation record, and distinguish branch computation from extra preview calls or actual deployment latency.
4. **Porting.** Reuse `cloq.run_arm` and `scripts/a6000/fork_driver.py`; the Ohio worker and serve scripts have hard-coded filesystem paths and need a Narval adapter. Preserve the worker's model revision, user/agent roles, tokenizer, parser, max lengths and deterministic serving flags. Run servers on compute nodes with staged offline weights and dependencies. Keep the prompt nonce identical across BF16 and W3 for a block. Let the baseline jobs produce complete trajectories before launching their matching forks, either in the same job or with Slurm dependencies and verified output. Keep the job array at an initial concurrency of 2 and derive wall time and GPU request from the smoke. Use separate agent GPUs or prove both 8B instances fit together before sharing one. Allow for the simulator's memory separately.

## 3. Follow-up experiments

- **Common states.** Select one ordinary state per task/block by a fixed hash on quantized histories before reading outcomes, including action agreements. On the same restored state run B, Q and Q′ as action sources, all with Q continuing. Start with Qwen3-8B GPTQ-W4 where both draws already exist. The primary paired contrast is `Y(B→Q) − Y(Q′→Q)`; add 4B as a replication and a second quantizer only once a matched second checkpoint is available.
- **Trigger.** Use independently held-out tasks in the same domains, excluding development, calibration and any previously inspected tasks. Freeze the existing margin threshold and run it on Q histories. Compare signed gain to no intervention and budget-matched random selection. Report captures, rescue/damage/net, and actual BF16 calls. If comparing DMR, distinguish a KL-only add-on from the trained KL+GRPO method, and account for extra BF16 forwards when the test-time policy uses them.
- **Damage traces.** Use archived divergent units with QQ success and BQ failure. Select by fixed hash, showing both cases recovered by BB and cases still failing under BB. Examine QB and the first changed tool result, unsatisfied requirement or exhaustion event. Include counts for each observed pattern before showing individual examples.
