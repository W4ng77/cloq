## 1. How `budget_ok` is computed

- `scripts/a6000/fork_driver.py:296` `budget_check(st, r)` returns `ok = (live == recount) and term_consistent and counters_tau2_default == [0, 0]`:
  - `live = [step_count_final, num_errors_final]`;
  - `recount = r["budget_recount"]`;
  - `term_consistent`: a `max_steps` ending needs live steps ≥ 200, and a `too_many_errors` ending needs live errors ≥ 10.
- `bank_u` (`fork_driver.py:770`) applies it per row, as `{arm: budget_check(...)["ok"]}`, over the arms that ran and have **no `error` key**. Reused arms (`orig`, `=XX`) are not checked.
- The summary (`fork_driver.py:787`) is `all(...)` over rows that have `Y`.
  - Manifest-missing rows (airline 13 in f01, airline 44 everywhere) have no `Y`, so they cannot affect it.
  - **Arm errors are skipped entirely.**
- `cloq/fork.py:589-600` handles `ContextWindowExceeded` (comment: "W10 / W70 … a valid failure outcome of the frozen policy: Y = 0"). It returns `budget_recount: None`, `suffix: None` and `prefix_ok: None`. Any overflow branch therefore yields `budget_ok = false`.
  - This is the same sentinel mechanism as W100i, which involved `prefix_ok: None`.
- `budget_ok` is read but never used:
  - `make_newmethod_panel.py:325-338` copies it into the expansion record, and none of the listed reasons uses it.
  - `analysis/fork/analyze_newmethod.py` (`load_tau2`, `strict_blocks`) never reads it. A row is excluded only for `missing_reason`, `error` or a `None` arm.

## 5. Rules applied (quoted; no new rule)

- **Overflow is a valid failure.**
  - RESEARCH_LOG W10: "a heavily perturbed agent looped until the dialogue exceeded the simulator's 65,536-token window. That is the agent's own failure … Analyses … count context_overflow as failure."
  - W70: "agent-side context overflow, which is deterministic and a valid failure (W10)".
  - `cloq/fork.py:589`: "a conversation that outgrows the simulator or agent window is the agent's own failure … Y = 0 under every evaluator."
- **Sentinels are not mismatches.**
  - SAMEPREC §4 (`docs/insights/SAMEPREC_PROTOCOL.md`): acceptance counts "are reported … but, as in the precision analysis, they exclude units only through quarantine."
  - W100i applied this to the identical overflow sentinel on `prefix_ok`.
- **Budget checks are gate criteria.**
  - FORK_PROTOCOL §7 (d) (`docs/insights/FORK_PROTOCOL.md`): "In every branch the live counters equal the recount of the produced trajectory" (engineering gate).
  - NEWMETHOD_PANEL_PROTOCOL §2.4.1 lists "budget ok" for `gate_same`.
  - The bank gate's `gate_pass` includes `budget_ok`.
  - Both m24 gates passed for both cells (`expansion_m24.json`).
  - FORK_PROTOCOL §15 amendment 1 (Bank U) has no budget-based admission rule: "Sampled states that fail are kept as missing, never replaced."
- **Expansion eligibility.**
  - NEWMETHOD_PANEL_PROTOCOL §5.2: "The gates passed (§2.4) and phase 1 is complete: f01–f03 done, n_errors 0, every no-op passed."
  - A5.2 lists the conditions (spec, provenance, `n_errors` 0, no-ops, `n_rows`, `n_missing`, `n_ok`). `budget_ok` is a field read, not a condition.
  - A5.2 limitation: "a branch-arm error inside an otherwise completed row … is counted in `n_ok` … Such a block passes A5.2. The analysis strict-block rule (§7; A3.3) still refuses it later. Expansion eligibility does not depend on it."
  - So `expand: true` stands.
- **Strict completeness.**
  - NEWMETHOD_PANEL_PROTOCOL A3.3: "A (cell, block) is admitted only if it has a complete four-arm state for exactly the 83 predefined tasks. Any newly missing branch (missing record, error, a missing arm) fails that block for that cell. Missing arms are never filled with zeros or otherwise imputed. Tasks are never retried until they succeed."
  - §7: "Cross-cell contrasts use the blocks complete in both cells."
  - A3.3: "The two-cell comparison uses blocks complete in both cells."
- **Where the rules are silent.**
  - No existing rule scores a fork-branch `agent_parse_error` as Y = 0.
  - W27 (`AGENT_SIDE`), W99p and `fork_driver.py:180` (source-episode `agent_parse_error` → "valid failure outcome (Y_QQ = 0)") cover closed-loop and source episodes. `run_branch` maps only `ContextWindowExceeded` to a valid failure.
  - The rules are also silent on whether a non-sentinel `budget_ok` failure should refuse a panel block, but none occurred.

## 7. Code gap (proposal only; no code changed)

- **`fork_driver.budget_check`**: on `infra_cause == "context_overflow"`, return `ok: None` ("not computable"). Still check `counters_tau2_default == [0, 0]`, live counters within limits, and `term_consistent`.
  - `bank_summary` would then report `budget_ok` over computable branches, plus `n_budget_sentinel` and a list of non-sentinel failures.
  - This is the same open display question as W100i.
- **`bank_u` summary**: add `n_arm_errors` and the list of `(state_key, arm, error class)`. The A5.2 limitation would then be visible without opening `bank_rows.jsonl`.
- **Expansion tool**: record these fields but do not add them as eligibility conditions. §5/A5.2 is frozen; a new condition needs an amendment.
- **`analyze_newmethod.strict_blocks`**: report per block the error class of each incomplete task and the budget breakdown.
- **Whether a non-sentinel budget failure should refuse a block**: this would be a new rule and needs a dated amendment.
